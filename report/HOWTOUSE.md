# Report 사용법

## 사용법

- ../WORKFLOW.md를 모두 통과한 inbox 후보에서 `submission.json`, 생성된 `REPORT.md`, `video/poc.mp4`, 선택적 `poc/`만 받는다. F-ID를 부여하고 복제하지 않는다.
- 이동 전 목적지 충돌을 확인한다. 이동 후 기존 경로 참조를 갱신하고 증거는 폴더 내 상대 링크로 연결한다.
- 형식·취급 조건은 ../project/RULES.md를 따른다. 제출은 별도 사용자 요청이 필요하며, 첨부 접근성과 민감정보 제거를 확인한다.
- 주장·영향·증거가 바뀌면 ../WORKFLOW.md에 따라 재검토한다.
- 신규 제출 후보는 `../scripts/RECORDING.md`의 실제 MP4 재생 검수 PASS가 필요하다. 영상 경로·확인 타임스탬프·결과를 REPORT.md에 적고 브라우저 프로필·쿠키는 이관·첨부에서 제외한다.
- 프로젝트 루트에서 `python3 scripts/prepare-submission.py report/F-ID --write-report`로 폼 필드와 영상을 검증한다. `fill-wordfence-form.js`는 명시적인 `--fill`에서만 열린 Wordfence 폼을 채우며 약관 동의와 Submit은 조작하지 않는다.
- WordPress 기술 후보는 탐색 에이전트 자체 검토 기록을 사용한다. 최종 외부 제출문은 새 독립 세션에서 제출문·필요한 증거·정책만 검토하고 그 결과를 기록한다.

## 외부 제출 폼

- 내부 증거 원문을 복사하지 않는다. Description은 취약한 입력·sink·최소 actor·영향만 짧게 적는다.
- PoC는 준비 조건, 단일 요청, 피해자 동작, 관찰 결과만 남긴다. 브라우저 XSS는 안전한 로컬 환경에서 즉시 식별 가능한 `alert(document.domain)` 형태를 우선한다.
- 해시·컨테이너 digest·음성 probe·검토 이력은 재현에 꼭 필요할 때만 넣고, 나머지는 로컬 증거에 보존한다.
- AI 사용 공개는 제출 폼의 전용 항목에만 정확히 적고 Description·PoC에 중복하지 않는다.
- 약관 동의, 사실 인증, 최종 제출은 사용자가 직접 확인한다.

## REPORT.md에 남길 검토 기록 — 실제 결과로만 작성

```markdown
- 최종 검토: <결론 · 검토자 · 일시 · 대상 버전/해시>
- 근거·한계: <판정 근거와 미해결 사항 / 없음>
- 제출: 미제출
```
